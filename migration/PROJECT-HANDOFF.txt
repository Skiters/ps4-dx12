КОНТЕКСТ ДЛЯ СЛЕДУЮЩЕГО ЧАТА / РАЗРАБОТЧИКА
Снимок от 09.10.2026, перенос с OneXPlayer 3 на более мощный компьютер.

ЦЕЛЬ И СОСТОЯНИЕ
Это отдельный форк shadPS4 с нативным графическим backend DirectX 12 и отдельным
Windows-меню библиотеки. Конечная цель — корректный вход в игру и стабильная
нативная производительность; после этого обсуждать апскейлинг/генерацию кадров.
Пользователь приостановил исследование движка. В этой итерации делалась только
упаковка/переносимость, а не новое исправление загрузки игрового мира.

Не утверждать, что Bloodborne уже работает в мире или достигнуты 60 FPS.
Нативно отрисовывались титульное/офлайн-меню и загрузочные экраны. Мир с
управляемым персонажем в текущем DX12-ядре визуально НЕ подтверждён. Загрузка
многократно оставалась на экране предметов, хотя GPU-команды продолжали идти.
Новый мощный ПК поможет измерениям, но не доказывает устранение ошибки движка.

ТЕКУЩИЕ КОМПОНЕНТЫ
work/shadps4-dx12-src — полный актуальный снимок исходников нашего форка.
  src/core — гостевой CPU, память, HLE, загрузчик, sysmodule и сигналы.
  src/video_core/amdgpu — разбор гостевых команд/регистров PS4.
  src/video_core/renderer_d3d12 — аппаратный D3D12 backend, очередь, rasterizer,
    представление VideoOut, геометрия, дескрипторы, буферы, текстуры, ретайлинг,
    CPU/GPU coherency и opt-in диагностика.
  src/shader_recompiler — гостевой GCN frontend/IR и компилятор.
  src/shader_recompiler/backend/dxil — обычная и linked конвертация в DXIL;
    унификация SSBO-доступов, связанная компиляция tessellation.
  desktop/Program.cs — WinForms-библиотека, поиск игр по SFO, выбор папок,
    геймпад, запуск ядра, диалог настроек и асинхронная установка PKG.
  desktop/pkg_worker.py — транзакционный установщик базовой игры/update/DLC.
  desktop/freeze_installer.py — сборка отдельного PKG-worker через PyInstaller.
  desktop/profile-template — чистый переносимый шаблон, без игры/сохранений.
  desktop/setup — Inno Setup .iss и Make-Installer.ps1.
  native-port — standalone GPU/CPU-тесты, host launcher и интеграционная сборка.
  migration — этот контекст, описание инструментов, dependency-lock.json,
    восстановление зависимостей, переносимые build-скрипты и исходные правки Mesa.
  NATIVE_DX12_PORT_STATUS.md — подробная история возможностей, исправлений и
    ограничений; старые абсолютные пути в ней являются историческими.

В установленном приложении:
PS4Desktop.exe -> native/shadPS4-DX12.exe -> native/core/shadPS4-DX12-Core.exe.
native/native-core-path.txt задаёт относительный путь core/shadPS4-DX12-Core.exe.
Host ждёт дочерний процесс и возвращает его exit code. Отдельный native-profile
используется как working directory. Никакого fallback на старое ядро нет.
--probe проверяет DX12-устройство/вывод, но gameLaunchReady остаётся false.
Экспериментальный запуск разрешён; надпись меню честно сообщает статус.

ИСХОДНАЯ БАЗА И СТОРОННИЙ КОМПИЛЯТОР
База: IFreemz/shadPS4-Bloodborne-DLSS-FSR, коммит
74c07f5e97ced220404d4baa2f8cf652463bbaa4.
Mesa: https://github.com/shadexternals/mesa.git,
b628375fb1fd99476bfbaaa0532deb6fe3a6870e (26.3.0-devel).
Наши 4 файла Mesa сохранены в migration/mesa-source-overlay. Это изменённый
meson.build плюс spirv_to_dxil.c/.def и spirv_to_dxil_linked.h. Восстановление
заменяет их в скачанной Mesa. Не терять их при обновлении зависимости.
SPIR-V служит только промежуточным форматом компилятора, исполняется DXIL/D3D12.
Вызовы Vulkan, его runtime и мост Vulkan->DX12 запрещены в нашем форке.
Тестируемая DLL компилятора входит в установщик; исходники для её пересборки
скачиваются заново по точному коммиту и дополняются указанными правками.

ПОСЛЕДНИЕ КОНКРЕТНЫЕ ИСПРАВЛЕНИЯ ДВИЖКА
- Валидность DB-плоскостей: устаревший stencil enable не требует отсутствующую
  stencil-плоскость. Depth bias поддерживает целые значения и дробный вариант
  только при проверенной OPTIONS16-поддержке D3D12.
- SSBO read/write в разных стадиях унифицированы в UAV; инструкции и настоящие
  гостевые записи сохраняются. Неподдерживаемый write-alias явно отвергается.
- Нулевые/невалидные ресурсы и CMASK имеют проверенные корректные пути.
- Текстуры/буферы ограничены бюджетами, in-flight данные не удаляются.
- Копирующий гостевой compute-HLE выполняет точные упорядоченные memmove после
  retirement предыдущих GPU-записей. Нет uploads/readbacks больших пустых щелей.
  GPU CopyBufferBatch остаётся реальным, отдельно тестируемым API.
- Проверка host backing использует coalesced ordered intervals. Успешные полные
  committed mappings публикуют читаемость/записываемость в rasterizer. Unmap/remap
  и защита инвалидируют/разрезают доказанные диапазоны. Reserved/PRT не выдаются
  за физически committed память. Это убрало наблюдавшиеся 100+ мс VirtualQuery
  задержки подготовки буферов, но ещё не доказало завершение загрузки мира.
- Гостевой JIT/AOT проверяет принадлежность RIP/диапазона настоящему модулю;
  предыдущая ошибка выбора ближайшего модуля могла приводить к invalid decode.

ОТКРЫТЫЙ БЛОКЕР ЗАГРУЗКИ
После исправления host validation остаются дорогие синхронные CPU/GPU операции.
Для 4096x4096 shadow/depth наблюдались full attachment readback/retile около
20 мс на draw. PrepareShaderBuffers в тяжёлых сценах стало значительно быстрее.
Последний stack snapshot показывал GPU в RememberSnapshot/DrawInternal, а
Core.Res.CacheableFileLoader — ожидающим InvalidateMemory из ReadFile.
Это кандидат для исследования, не доказанный deadlock или сбой драйвера.

ЕЩЁ НЕ ПРИМЕНЁННЫЕ ИДЕИ
1. InvalidateMemory сейчас может Find/Upload старые данные даже для только что
   выделенной области file read. В file_system.cpp уведомление вызывается ДО
   чтения файла. Рассмотреть корректную lazy invalidation без преждевременного
   GPU materialization. Сначала сохранить порядок Finish, CPU writes и соседние
   GPU dirty bytes; существующие coherence-тесты должны оставаться правильными.
2. execution_mutex_ — recursive_mutex, draw держит её долго. Возможно голодание
   CPU/file-loader. FIFO/fair recursive lock требует настоящего contention-теста;
   не называть ожидание доказанной взаимной блокировкой без дополнительного лога.
3. Уменьшить full retile/snapshot-копирования, сохранив padding, tiling, guest
   coherency и ownership. Нельзя просто пропускать draw/readback или подменять
   изображение ради якобы успешной загрузки.
Эти направления не были реализованы перед паузой.

ПЕРЕНОСИМОСТЬ МЕНЮ, ДОБАВЛЕННАЯ В ЭТОЙ УПАКОВКЕ
Новые настройки и профиль живут в %LOCALAPPDATA%/PS4Desktop. Defaults больше не
ссылаются на Bloodborne-Portable или старого пользователя. Настройки рядом с
exe читаются только для совместимости со старой ручной установкой; установщик
их не кладёт. Profile-template создаёт отдельные home/addcont/sys_modules/fonts.
Пустая библиотека допустима. RunWorker("install") сначала подготавливает профиль,
поэтому DLC не создаёт полупустой native-profile без config.json.
PS4DESKTOP_DATA_ROOT — override для разработческих проверок в отдельной папке.
NativeLaunchPolicy удаляет наследуемые diagnostic/startup/validation/log-override
и SHADPS4_BENCH_GAMEPAD переменные из обычного запуска дочернего ядра.

ПРАВИЛА ПРОДОЛЖЕНИЯ
Не менять драйверы, Windows, службы, питание, affinity или систему ради этой
задачи. Работать в форке, отдельно от оригинального Vulkan-приложения.
Генерация кадров, XeSS/XMX, FSR/RCAS/HDR пока выключены/не интегрированы. Нельзя
выдавать синтетические векторы движения за настоящие входы XeSS. Сначала мир.
Запускать/закрывать игру для проверки пользователь разрешал; навигация внутри
игры должна быть геймпадом. Обычный запуск без сборщиков метрик/истории.
Диагностика разрешена только явно в собственном тестовом процессе. При изменении
core сохранять точный SHA256 и matching map; не разрешать stack по чужой сборке.
Считать успехом именно изображение мира и управление персонажем, не меню/FPS
загрузочного экрана. Более мощное железо оценить измерениями после запуска.

РЕКОМЕНДУЕМЫЙ ПЕРВЫЙ ШАГ СЛЕДУЮЩЕГО ЧАТА
Прочитать этот файл и INSTALL-DEVELOPMENT.txt, проверить папки нового компьютера,
установить средства разработки, восстановить pinned зависимости, собрать core
и базовые GPU/CPU-тесты. Не возвращаться к отключённой генерации до решения
нативной загрузки. Runtime ядра в установщике оставлен точно E355...; перенос
ничего не объявляет исправленным сверх перечисленных подтверждённых проверок.
